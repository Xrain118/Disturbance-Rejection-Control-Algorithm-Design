# 双臂串口遥测协议 v1

整理日期：2026年10月18日。实现状态与验证范围见[当前进度](../当前进度.md)和[验证记录](verification-20261018.md)。

## 传输与调度

ESP32—上位机：921600 baud、8N1、无流控，UTF-8 换行 JSON；ESP32—舵机：保持 1 Mbps。两者独立配置，不猜测或自动切换。初始化及原有上电姿态指令完成后，采集任务默认目标 50 Hz。采集不在中断中，不等待主循环动作完成。每次事务初始绝对预算 2 ms（包含锁等待），每轮最多 15 ms；这些是软件预算，FreeRTOS 抢占下的实测最坏时延未验证。

命令访问和反馈读取共用事务锁，反馈包核对 ID、长度及校验和。每轮七个新槽位，失败不复制上一轮值。连续扫描七舵机并非同时采样；时间戳是 ESP32 完成读取的时刻，不能解释为舵机 ADC 时刻。

独立发送任务输出完整行。遥测队列容量一帧，积压丢弃旧的待发送帧，保留最新完整帧；正在发送的行不截断。日志队列容量四行，过载丢弃。所有应用日志经过同一输出通道；ROM 启动信息可能以不同波特率出现，主机必须能忽略非法行。

目标周期 20 ms，迟到跳过错失周期，不追赶发送旧样本。即使新版流关闭，采集任务仍更新旧消费者需要的快照。动作期间配置命令须等主执行上下文处理，不保证实时响应或抢占运动。配置指令不具有急停语义。

## T=1052 帧

可执行样例见[有效测试向量](../src/dragonfly_serial/test/data/valid.json)及[边界向量](../src/dragonfly_serial/test/data/worst.json)。

| 字段 | 类型与意义 |
|---|---|
| `T`, `ver` | 整数 1052、1；不兼容版本拒绝 |
| `dev` | eFuse MAC 派生的稳定十六进制标识，非左右标签 |
| `boot` | 本次启动随机 uint32 标识；不是密码学身份或绝对唯一保证 |
| `seq` | uint32 采集序号，可回绕；启停期间也继续采集计数 |
| `t_us` | uint64，ESP32 启动后的本轮采集结束时间，µs |
| `rate` | 目标采集/上报频率 1～50 Hz，不代表实际测得频率 |
| `scan_us`, `overrun`, `dropped` | 本轮采集耗时、累计错失周期、累计遥测丢弃数；uint32 |
| `method`, `cal`, `params` | `factory_linear`、`uncalibrated`、`factory-v1` |
| `ids` | 固定 `[11,12,13,14,15,16,17]` |
| `ok` | 七个布尔值；表示本轮完整总线读取成功，不证明力矩精度或速度单位正确 |
| `pos`, `speed`, `current`, `load` | 七项带符号原始值；保留寄存器符号语义 |
| `voltage`, `temperature` | 七项原始 byte；本接口按 0.1 V、°C 映射，硬件型号仍需核实 |
| `status`, `error` | 状态寄存器及总线回复错误字节；不掩盖设备故障标志 |
| `tau` | 七项物理舵机输出力矩粗估，N·m |
| `read_us` | 七项读取完成时间；成功项不晚于 `t_us` |

`ok[i]=false` 时，该舵机上述所有测量及 `read_us` 必须为 `null`。合法 `current=-1` 是测量值，不是失败哨兵。有效读取但非零故障状态可以上报，消费者仍须检查故障。旧快照不能冒充本轮测量。

默认力矩公式：

```text
I_A = current_raw × 0.0065
tau_i = Kt_i × 0.0065 × (current_raw_i − electrical_zero_raw_i)
Kt_11..16 = 1.0787315 N·m/A
Kt_17 = 0.81395195 N·m/A
electrical_zero_raw_i = 0
```

系数为用户指定初值，预期 ID11～16 为 ST3215、17 为 ST3215-HS，需实物核查。逐舵机数组可替换；更改参数须同时更改参数版本。无附加负载时的同姿态电流包含重力、摩擦等，不作为电气零偏自动扣除。原始值及粗估值默认不平滑。

固件帧上限为 1200 字节（含换行），静态断言保证 `1200×50×10 / 921600 ≈ 65.1%`，低于 70%。该预算只针对遥测，不是任意日志洪泛时的保证。序列化溢出整帧丢弃并计数，不截断字段。主机防御性行长上限 2048 字节；超长行丢弃至下一个换行。

## 配置和旧模式

```json
{"T":606}
{"T":606,"enable":true,"rate":50}
{"T":606,"enable":false}
```

回复示例：`{"T":6061,"ok":true,"enable":true,"rate":50,"ver":1,"dev":"..."}`。非法频率或字段类型整次拒绝；未给字段保持原值，纯查询不更改配置。配置仅 RAM 保存。启用新版流时关闭旧自动输出；`T=605` 显式切到旧模式并关闭新版流，旧 `cmd=2` 自动流最多 10 Hz。`T=105` 及其 `1051` 回复保留按需查询。

新固件切旧输出模式仍保持 921600；上位机 `protocol: legacy` 默认选择 115200 是为未更新的旧固件。与新固件旧输出模式配合时，必须显式设 `baud: 921600`。旧模式没有设备身份、逐舵机有效性、当前采集时间或本协议力矩，不伪造这些信息。

## 主机语义

左右端口独立接收/重连，禁止同一实际路径或别名。配置 `device_id` 后严格核对；未配置时仅锁定本次运行首次接受的身份，无法保证第一次左右没有接反，部署时应填写。序号重复、逆序、同启动标识时间倒退、身份错误均拒绝；重启/丢包会重置可选滤波。

`ArmTelemetry.header` 为主机接收墙钟时间，原始设备时间独立保存。ROS 中整数无法表示 null，必须先检查 `valid`：无效整数是默认占位，浮点为 NaN，不能将占位 0 当测量。原始 JSON 保留 null。旧协议 `legacy=true`、`servos=[]`、时间/计数默认占位，意味着未知。

每侧五轴位置使用物理索引 11、12、14、15、16。位置零位/方向按现有固件映射，并提供独立覆盖参数。肩从动 13 和夹爪 17 不冒充额外五轴运动关节。力矩方向独立可配，初始五轴合成为 `[-τ11, τ12−τ13, τ14, τ15, −τ16]`；肩两个来源缺一则无效，全部机械方向待实测。

`JointState.effort` 留空。速度仅在用户显式给出 `speed_rad_s_per_raw>0` 且确认舵机配置后换算，否则留空。独立滤波 topic 仅在 `filter_alpha>0` 时发布，原始和未滤波力矩不改写；断连、过期、重启、序号缺口重置滤波状态。

诊断分别记录每臂连接、新鲜度、接收平均频率、序号缺口、重启、解析错误、采集无效数、故障数、超期和发送丢帧。默认 0.5 s 是软件观测阈值，不是已验证实飞失效阈值。有效数据也标为 WARN，提醒力矩未标定。无效关节不发布伪造 JointState；下游必须同时使用质量接口，不能永久持有最后状态。

JSONL 保存 `side/kind/raw/mono_ns/wall_ns`，以及连接、配置、帧错误和解析错误事件。记录开始保存每臂换算参数、身份、协议模式、滤波与过期阈值；回放恢复这些换算配置，端口元信息不会触发任何串口打开。旧记录没有配置事件时使用启动参数。磁盘写入失败在诊断中显示，采集继续。回放复用解析与质量检查，不接触硬件；不将主机墙钟与 ESP32 时间直接相减作为传输时延。
