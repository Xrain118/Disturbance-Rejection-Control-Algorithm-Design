# 第一版在线耦合动力学、动力学前馈与飞控六维 wrench 串口接口实施计划

日期：2026年11月1日  
状态：**第一版代码已接入，纯计算测试通过；ROS／PX4／SITL 尚未验证**  
修订说明：根据用户确认，机载电脑输出三维力和三维力矩，动力分配保留在飞控侧。用户已批准开始实施；本文件继续作为验收清单。  
范围：第一版可运行代码、仿真验证、飞控串行通信接口及无桨台架验证准备。  
执行边界：本计划不包含 Git 提交，不允许把 SITL 结果表述为实机验证结果。

## 1. 目标

在现有 Dragonfly 仿真和双臂遥测基础上，形成以下最小闭环：

1. 根据浮动基座与双臂状态，在线计算耦合动力学基座项。
2. 根据明确的名义模型计算动力学前馈差量，而不是重复叠加完整机械臂 wrench。
3. 机载电脑合成并输出三维力和三维力矩，即六维 `W_cmd=[F_x,F_y,F_z,T_x,T_y,T_z]`。
4. 通过飞控串行通信链路，将六维 wrench 对应的 PX4 推力／力矩目标发送给 PX4。
5. PX4 在研究模式下保留状态估计、Dragonfly 控制分配、执行器输出及经验证的失效处理；机载电脑承担研究模式的位置／姿态反馈和模型前馈。
6. 第一版在 SITL 中完成可重复对照，并为真实飞控的无桨台架测试提供接口和检查项。

第一版不纳入残余扰动观测器、实机自由飞行、机械臂关节抗扰、末端世界坐标稳定和接触力控制。

## 2. 当前基础与方案可行性

### 2.1 可直接复用的基础

- `model.py` 已能从 URDF 合成指定构型的整机质量、质心和惯量。
- `core.py` 已有基础 PD／重力补偿和旋翼—倾转作用模型；其中的 Python 分配器只作为旧调试参考，不是本方案的机载分配环节。
- `arms.py` 已能生成带位置、速度和加速度的平滑机械臂轨迹。
- 原生 `px4_native` 已贯通 PX4 状态估计、飞行反馈、Dragonfly 控制分配及六电机六倾转输出。
- 当前 PX4 适配已有 `VehicleThrustSetpoint`、`VehicleTorqueSetpoint` 的遥测和物理量／归一化量重建依据。
- `dragonfly_serial` 已有独立串口线程、有界队列、显式端口、时间戳和诊断经验，但其当前协议只面向双臂 ESP32。

### 2.2 可行性判断

**该方案可行，而且比“机载电脑输出十二路执行器指令”更贴合现有 PX4 适配。**

推荐链路为：

**机载 ROS 2 节点 → Micro XRCE-DDS Agent → UART／USB 串口 → PX4 uXRCE-DDS Client → PX4 推力／力矩目标接口 → Dragonfly 控制分配器 → 六电机与六倾转输出。**

理由：

- 机载电脑只负责生成六维 wrench，现有 `ControlAllocationDragonfly` 继续负责推力、倾转角、倾转速率和执行器约束。
- 可以复用现有分配反馈和 `control_allocator_status`，避免另建一套机载十二路分配及其一致性验证。
- 现有工程已经使用 PX4、`px4_msgs` 和 uXRCE-DDS，无需为第一版自造原始串口协议。

需要明确：

1. **研究模式只绕过 PX4 原生位置／姿态反馈环，不绕过 PX4 控制分配器。** 不使用 `direct_actuator`，也不由机载电脑发布 `ActuatorMotors`／`ActuatorServos`。
2. **PX4 的推力和力矩目标消息不是直接的 N、N·m 物理量。** 机载内部计算物理 wrench，发送前必须转换为 FRD 下的归一化目标。
3. **原生反馈环与研究反馈环必须互斥。** 原生位置／姿态控制器不能与研究模式同时竞争推力／力矩目标发布权；但 PX4 分配器在两个模式中都可保留。
4. **力矩参考点必须明确。** 机载内部统一为 FLU、关于 `uav_base_link` 原点；适配时处理质心偏移和 FLU／FRD 转换。
5. **串行发送不等于取消安全机制。** 仍需 Offboard 存活、模式所有权、目标过期处理及明确接管策略。
6. 以下计划按“PX4 飞控及其现有 Dragonfly 分配器”理解。如果实际接收六维 wrench 的是另一块独立动力分配板，则需要其通信协议和输入语义，不能直接套用 PX4 消息方案。

## 3. 推荐总体架构

```text
PX4 导航状态 ───────────────────────────────┐
                                            v
参考轨迹 ──> 机载基础反馈 ──> 期望基座加速度 ──> 名义 wrench ─┐
                                                              │
双臂目标轨迹／实际反馈 ──> 状态对齐 ──> 耦合动力学 ────────────┤
                                            │                 │
                                            ├─ 左右臂诊断 wrench（不直接叠加）
                                            └─ 前馈差量 ΔW_model
                                                              │
                                                              v
                                                    W_cmd = W_nom + ΔW_model
                                                    三维力 N＋三维力矩 N·m
                                                    FLU／关于机体原点
                                                              │
                                                              v
                                            坐标、质心参考点与归一化适配
                                                              │
                                      VehicleThrustSetpoint＋VehicleTorqueSetpoint
                                                              │
                                                uXRCE-DDS over UART
                                                              │
                                                              v
                                      PX4 Dragonfly 控制分配及分配反馈
                                                              │
                                                              v
                                            6 ESC＋6 倾转伺服硬件输出
```

原生 PX4 模式和研究模式保持互斥：原生模式由 PX4 生成推力／力矩目标；研究模式由机载电脑生成目标。两种模式都使用 PX4 的 Dragonfly 控制分配器，不允许同一时刻存在两个目标发布者。

## 4. 代码与包组织方案

### 4.1 飞控接口的归属

功能上属于“串口通信模块”，但建议新建独立包：

```text
src/dragonfly_fcu_bridge/
```

不建议直接把 PX4 依赖加入现有 `dragonfly_serial`，原因是：

- 当前 `build_hardware.sh` 明确支持只安装轻量遥测依赖，不依赖 PX4。
- 双臂 ESP32 采集与飞行安全关键输出应使用不同节点和故障域。
- 飞控接口实际由 XRCE Agent 持有串口，不需要复用 ESP32 的 `pyserial.PortWorker`。

如果评审坚持放在 `dragonfly_serial`，备选方案是新增独立的 `fcu_bridge.py` 节点和单独构建配置，但不得影响现有仅采集构建，也不得与 `dual_arm_serial` 共用控制状态。

### 4.2 建议文件

```text
src/dragonfly_flight/dragonfly_flight/
├── coupled_dynamics.py       # 纯耦合动力学计算
├── model_state.py            # 状态、时间戳、来源和有效性
├── feedforward.py            # 名义模型、补偿差量、启停和限幅
└── runtime.py                # 数据接入和模式调度，不堆放公式细节

src/dragonfly_interfaces/msg/
└── BodyWrenchCommand.msg     # 机载内部六维物理 wrench

src/dragonfly_fcu_bridge/
├── dragonfly_fcu_bridge/
│   ├── wrench_adapter.py     # 物理 wrench 到 PX4 归一化目标的纯函数
│   └── fcu_bridge.py         # px4_msgs 发布、状态和诊断
├── config/
│   └── fcu_bridge.yaml       # 名义尺度、限幅和超时配置
├── launch/
│   └── fcu_bridge.launch.py
└── test/
    ├── test_wrench_adapter.py
    └── test_fcu_bridge.py
```

构建调整只加入飞行构建和测试入口；现有硬件采集构建继续只选择原有两个包。

## 5. 接口约定

### 5.1 机载内部六维 wrench

`BodyWrenchCommand` 至少包含：

- `header.stamp`：控制量生成时刻。
- `header.frame_id`：固定为 `uav_base_link`，表达机体系 FLU。
- `force_n[3]`：三维力，单位 N。
- `torque_nm[3]`：三维力矩，单位 N·m。
- `torque_reference_point`：固定为 `uav_base_link` 原点。
- `valid`：整组指令有效性。
- `sequence`：单调序号。
- `model_version`：模型和参数版本。
- `source_mode`：基线／前馈等来源模式。

力和力矩使用相同控制时刻，不得把不同时间或未对齐的两组数据拼成一个 wrench。

### 5.2 PX4 推力／力矩目标适配

独立纯函数完成：

```text
BodyWrenchCommand（FLU，力矩关于 O）
→ 力矩参考点由 O 转换到标称质心 C
→ FLU 转 FRD
→ 使用同一模型版本的质量、惯量和尺度归一化
→ 非法值与限幅检查
→ VehicleThrustSetpoint／VehicleTorqueSetpoint
```

按当前 Dragonfly 适配约定，设 `D=diag(1,-1,-1)`，则适配关系为：

\[
u_F=\frac{D F^B}{m_\Sigma a_s},
\qquad
u_\tau=\frac1{\alpha_s}D I_{\Sigma,C}^{-1}
(\tau_O^B-c_\Sigma\times F^B).
\]

这里的 `mΣ`、`cΣ`、`IΣ,C`、`a_s` 和 `α_s` 必须来自同一个生成模型和 PX4 参数版本，不能在配置中手工复制出另一套不一致参数。

要求：

- 研究模式使用推力／力矩 Offboard 语义，关闭位置和 `direct_actuator` 输出语义。
- 过期指令不继续作为新指令发送；不得默认把“零推力”当作所有场景都安全的失效动作。
- 重连后不自动重放旧控制帧。
- Offboard 心跳和模式切换只有一个所有者，桥接节点不得与 `runtime.py` 争夺模式控制。
- 订阅 PX4 分配状态和实际限幅后的执行器输出，用于记录分配残差及后续执行器作用估计。

### 5.3 动力学输入输出

输入：

- 基座姿态、机体系线速度和角速度。
- 双臂十关节位置、速度和加速度。
- 各输入的采样时刻、来源、有效性和模型版本。

输出：

- `M_bb`、`M_ba`、`h_b`。
- 左右臂对基座的诊断 wrench。
- 输入有效性和计算耗时。

第一版前馈优先使用平滑目标轨迹的 `q_ref/dq_ref/ddq_ref`；实际反馈模式在轨迹预测模式验证后增加。不得直接对含噪串口位置无滤波二次差分。

## 6. 分阶段实施

### 阶段 0：冻结接口与实机核查项

工作：

1. 核对 PX4 v1.16.2 实际构建中推力／力矩输入话题、Offboard 语义、Dragonfly 分配器和输出模块。
2. 确认真实飞控型号、UART／USB 接口、XRCE Agent 传输方式和可用波特率。
3. 确认研究模式下原生位置／姿态反馈退出、PX4 分配继续运行的配置和证据。
4. 核对质量、质心、惯量、加速度尺度和角加速度尺度与 PX4 参数的一致性。
5. 单独评审失效处理，不沿用 SITL 的“终止仿真”作为实机策略。

完成条件：形成可检查的消息表、坐标与参考点约定、模式所有权表和台架安全前置条件。未确认项必须保留为未确认，不填猜测值。

### 阶段 1：纯耦合动力学模块

工作：

1. 从同一 Xacro／URDF 构建“自由浮动基座＋十关节”模型，锁定倾转及旋翼相对自由度。
2. 优先评估 Pinocchio 作为在线刚体动力学求解器；保留 NumPy 特殊工况参考检查。
3. 实现 `M_bb`、`M_ba`、`h_b` 和左右臂诊断 wrench。
4. 固定 ENU／FLU、平移在前转动在后、力矩关于 `uav_base_link` 原点的约定。
5. 不在线求 `M^-1` 做正动力学；前馈使用期望加速度进行逆动力学计算。

完成条件：纯计算测试通过，不依赖 ROS 话题和 Gazebo 真值。

### 阶段 2：在线影子运行

工作：

1. 接入 PX4 导航状态和双臂平滑轨迹状态。
2. 保留采样时刻和接收时刻，按控制时刻对齐状态。
3. 在线计算并记录动力学输出，但暂不改变控制量。
4. 记录单次计算耗时、输入年龄、无效次数和模型版本。
5. 第一版复用当前仿真 100 Hz 调度，实测后再决定实机频率。

完成条件：固定臂、展开和左右臂标准动作期间无非法输出；名义构型且关节静止时补偿差量接近零。

### 阶段 3：动力学前馈与六维 wrench 输出

工作：

1. 将基础控制器拆分为“期望基座加速度”和“名义 wrench”两个明确步骤。
2. 计算：

   \[
   \Delta W_{model}=(M_{bb}-M_{bb}^0)\dot\nu_b^\star
   +M_{ba}\ddot q_a+(h_b-h_b^0).
   \]

3. 合成 `W_cmd = W_nom + ΔW_model`，并加入独立启停、幅值限制、有效性退化和日志。
4. 输出 FLU 下的三维力和关于 `uav_base_link` 原点的三维力矩，不在机载侧进行十二路动力分配。
5. 记录请求 wrench、PX4 分配后可实现 wrench 和分配残差，不将请求值当成实际执行器作用。

完成条件：前馈关闭时严格复现 B 组；前馈开启时 C 组日志可解释，且没有重复加入完整机械臂重量。

### 阶段 4：飞控六维 wrench 串行接口

工作：

1. 新建独立 `dragonfly_fcu_bridge` 包和 wrench 归一化适配测试。
2. 新增 `px4_wrench` 研究模式，发布推力／力矩目标，不使用 `px4_actuators` 作为正式研究链路。
3. 先在现有 SITL 传输中验证消息、模式互斥和 PX4 分配结果。
4. 再将 Agent 与 PX4 的传输切换为实际 UART／USB 串口。
5. 增加连接、序号、消息年龄、发送频率、分配残差和非法输出诊断。
6. 在无桨、固定机架、执行器可安全断电的条件下核对 PX4 十二路输出。

完成条件：机载物理 wrench、PX4 接收目标和分配器输出可逐项对照；断开、过期和重连行为符合已评审策略。

### 阶段 5：第一版仿真验收

顺序：

1. `ideal_wrench`：排除执行器分配影响，检查前馈符号和基本响应。
2. `px4_wrench`：经过机载 wrench 适配、串行消息接口、PX4 Dragonfly 分配和旋翼／倾转物理模型验证完整链路。
3. 检查 PX4 的分配状态、六电机和六倾转输出，确认研究模式未绕开分配器。
4. B／C 同工况比较：相同轨迹、双臂动作、参数、步长和随机种子。

第一版验收不包括实机自由飞行，不宣称抗扰算法已经优于基线；只声明代码链路、测试和实际观察结果。

## 7. 最小测试集

### 7.1 动力学

- 质量矩阵对称、正定、有限值检查。
- 静态双臂重力和重力矩方向检查。
- 理想共同自由落体时界面反作用接近零。
- 单关节正负加速度的反作用符号检查。
- 完整耦合方程与逐刚体求和的一致性检查。
- 参考点旋转和平移检查。
- 名义构型、关节静止时前馈差量为零。

### 7.2 前馈与 PX4 分配

- 前馈启停无残留状态。
- 无效或过期关节状态不会继续产生前馈。
- 固定臂时无重复机械臂重量补偿。
- PX4 推力、倾转角和倾转速率约束仍然有效。
- 不可达 wrench 产生可记录的分配残差。

### 7.3 飞控接口

- 六维 wrench 坐标、力矩参考点和模型版本检查。
- 物理 wrench 与 PX4 归一化目标往返检查。
- NaN、Inf、错误坐标、错误参考点和错误版本拒绝测试。
- 指令过期、断连和重连测试。
- 原生与研究模式目标发布权互斥测试。
- PX4 接收目标、分配结果和十二路输出的一致性检查。

### 7.4 对照记录

保存参考与实际机体状态、关节目标与反馈、`W_nom`、`ΔW_model`、`W_cmd`、PX4 归一化推力／力矩目标、分配输出与残差、模式事件、输入年龄、计算耗时、参数和代码版本。

## 8. 主要风险与处理

| 风险 | 后果 | 第一版处理 |
|---|---|---|
| 自造飞控串口协议 | 固件开发和验证范围显著扩大 | 优先复用 uXRCE-DDS over UART |
| 原生与研究反馈环同时运行 | 推力／力矩目标竞争 | 模式互斥和唯一目标发布者检查 |
| 研究模式误用 `direct_actuator` | 绕过现有分配器及其反馈 | 使用推力／力矩目标接口，保留 PX4 分配 |
| FLU／FRD 或力矩参考点错误 | 补偿方向或力矩尺度错误 | 独立适配函数和往返／已知作用测试 |
| 动力学参数仍有估算 | 前馈幅值和相位误差 | 影子运行、敏感性分析，暂不承诺实机收益 |
| 状态不同步或关节加速度噪声 | 错误前馈和额外扰动 | 先用平滑轨迹；反馈模式后续验证 |
| 串口／DDS 时延和丢包 | 控制相位滞后、旧指令执行 | 时间戳、有效期、实测链路预算和失效策略 |
| 失效时直接停桨或切原生 | 可能造成更大风险 | 单独评审，不能自动继承 SITL 动作 |
| 桥接节点与遥测节点耦合 | 一个串口故障影响另一个系统 | 独立包、独立节点和独立故障域 |

## 9. 请用户评审的决策点

1. 控制边界确认为：**机载电脑输出六维 wrench，PX4 保留 Dragonfly 控制分配和十二路执行器输出。**
2. 是否同意飞控链路优先采用 **uXRCE-DDS over UART**，第一版不开发自定义原始串口协议。
3. 是否同意飞控接口逻辑上属于串口通信层，但代码放入独立的 `dragonfly_fcu_bridge` 包，以保持现有双臂采集包的轻量依赖。
4. 是否同意第一版以 **SITL 完整链路＋无桨台架接口核对**为边界，不包含实机自由飞行。
